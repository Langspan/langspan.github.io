# Design review contract

## Recovery reference
The maintainer identified deployed commit `98883c6` as the preferred visual
baseline. The recovery commit restores the exact website tree from #21,
which retains the original #20 visual implementation while keeping site-only
deployment and SEO hygiene. It undoes #22's broad scene-layout changes without
rewriting the history of main.

## Brief
- Audience: engineers already running multiple coding agents.
- Primary job: install the released LangSpan binary.
- Preserve approved wordmark, warm-white/near-black/coral palette, existing
  page hierarchy, actual vendored Stageshow scenes and real captured evidence.
- Do not add another animation runtime, a framework migration, placeholder
  product screenshots, invented reviews or benchmark results.
- Explain actual behavior in existing scenes. Make narrow-screen compositions
  deliberate, with no disconnected connectors or clipped terminal text.
- For motion changes: default loops only while visible, meaningful holds at
  final beats, static reduced-motion state and clear manual pause.
- Keep pending engineering features visibly separate from released capabilities.

## Evidence and review
Hallmark and Taste Skill are audit inputs, not automatic redesign engines.
Use their actual pinned scripts in the visual review job. Review their findings;
do not claim a pass or add a certification stamp just because a command ran.
Existing brand and precise CLI labels are intentional, but genuine accessibility,
layout, copy and motion problems must be fixed before a new release.

Read the upstream frontend-design, Marketing Skills CRO, product-showcase and
landing-page-guru guidance. For this site, real product evidence means captured
CLI/dashboard behavior from the released binary; diagrams and Stageshow
illustrations must remain honestly labeled. Conversion is an outcome to measure,
not a property proven by a linter.

For each candidate, retain the exact checkout, desktop and narrow viewport
captures of all key scenes, actual motion-loop review, reduced-motion and
no-JavaScript checks, and source/build integrity. Browser interaction tests
alone do not establish visual quality. The maintainer reviews the rendered
candidate before a merge or deployment. This branch is not a live-site release.
